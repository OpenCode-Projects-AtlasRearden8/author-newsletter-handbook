# Issue Template

> The skeleton for one regular issue, plus the "minimum lovable issue"
> rule enforced below. Copy the skeleton each issue, fill it, cut it.
> The [calendar](issue-calendar.md) tells you when; chapter 7's pipeline
> tells you how.

## The one-sentence promise (fill this first)

Before any writing: complete this line. The whole issue hangs from it,
and the subject line usually falls out of it (chapter 5).

```text
After reading this, [one real reader] will [one specific thing be able to do / understand / feel].
```

## The skeleton

```text
Subject: [topic-ish, below ~45 characters, from the promise above]
Preheader: [the second sentence: the payoff, not a repeat]

Hi [there / first-name],

[HOOK -- 2-3 sentences, in media res: last week I..., or a reader
question, or the mistake that taught you the thing. No weather. No
"In today's fast-paced world." The issue starts mid-thought.]

[THE USEFUL THING -- the one idea this issue delivers. Small, concrete,
yours. This is the part worth archiving; if it took a table, it gets a
table.]

[THE STORY BEAT -- one personal, true paragraph. What actually happened
to you this month, told plainly. The newsletter's substance lives here
more than anywhere (chapter 6).]

[THE ONE LINK -- the single next step: an essay, a tool, your book page,
or the reply prompt. One.]

[FOOTER -- cadence reminder + unsubscribe][the provider puts this in;
do not decorate it]

[Your name]
```

## The minimum lovable issue checklist

Three boxes. Ship the draft only when all three are true; ship sooner
when none is threatening to become a fourth.

- [ ] The promise line above is written and specific.
- [ ] There is exactly one thing a reader could use tomorrow morning.
- [ ] There is one true personal beat (chapter 6's rule: if you would
      not say it across the street, it goes).
